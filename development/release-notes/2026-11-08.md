# Release Notes: 8 November 2026

## 1. The Studio

In this update the Urban Science Workbench gains the Studio, a page of its own for making figures with live code ([ADR 0081](../decisions/0081-the-studio.md)). It is an initial implementation for feedback. See the [gallery's §19](../../docs/gallery.md).

- **A figure as a canvas.** A project is one canvas of frames, each placed and sized by hand: the 3D world with its own globe, camera and clock, a 2D map following it, charts, drawings and text. The whole canvas is exported as one image at twice its size, with its charts as vector.
- **Scripts in three languages, while it runs.** Write a script in JavaScript, Python or C++ while the project plays. Save it, and it is loaded (compiled, for C++) and joins the next tick. Each script can be paused, stopped, started again or deleted. A version that does not compile has its line marked, and the version before keeps running.
- **What a script knows and draws.** A script is given the view's range in space and time: where it looks, the ground it sees, its heading, its metres to a pixel, the moment, and every frame's size. It draws on the world, or into any frame as a chart or a drawing of its own. The example north arrow and scale bar is such a script.
- **Shared content in a sound order.** Scripts share named resources. The order they run in follows from what each reads and writes. Rules that would make the result depend on chance are refused with a reason: two writers without a merge, or a loop with no delay.
- **The world's data, and Explore's views.** The data library's records go on the world as layers that scripts can read. A chart can follow any resource with no code at all. Explore gains two keys only: *capture* keeps the view for a project, and *studio* opens the Studio.

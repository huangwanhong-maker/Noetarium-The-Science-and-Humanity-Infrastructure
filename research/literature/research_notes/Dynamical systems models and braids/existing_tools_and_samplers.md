"Windows wheel" means that the newest release on PyPI has a file usable on Windows x64 with CPython 3.12 (a pure-Python wheel, or a `win_amd64` wheel tagged `cp312` or `abi3`). ## 1. Continuation and Bifurcation: AUTO-07p, MatCont, XPPAUT, PyDSTool, BifurcationKit.jl, COCO, DDE-BIFTOOL, pde2path

### Takeaway
BifurcationKit.jl (MIT, v0.8.9, active) is the only one of these that is permissively licensed, scriptable, actively released and documents normal forms for codimension-2 points of equilibria; MatCont (MATLAB, GUI) remains the reference for normal-form coefficients, including periodic normal forms, and AUTO-07p for boundary-value continuation without normal forms. Published numbers that can be used as cross-checks exist in BifurcationKit's Lorenz-84 tutorial (the same model is treated in MatCont).

### Cited Findings

**AUTO-07p**
- Described by its README as software for "continuation and bifurcation problems in ordinary differential equations", "originally written in 1980"; it "incorporates both a Unix and a Python command language user interface (CLUI)"; the README still calls it "a beta version of AUTO-07p" — [auto-07p README](https://github.com/auto-07p/auto-07p)
- Latest tag v0.9.3 (2021-08-25); previous 0.9.2 (2019-11-28); last push to the repository 2025-06-26; main language Fortran; GitHub detects no licence file — [releases](https://github.com/auto-07p/auto-07p/releases), [repository](https://github.com/auto-07p/auto-07p)
- SourceForge lists its licences as "BSD License, GNU General Public License v2.0 (GPLv2), GNU Library or Lesser General Public License v2.0 (LGPLv2)", languages C, C++, Fortran, Python, and says the project moved to GitHub as of 2019-11-29. **[mixed; treat as GPL/LGPL-encumbered until checked file by file]** — [SourceForge auto-07p](https://sourceforge.net/projects/auto-07p/)
- Detection is by test functions: folds from the last component of the tangent vector; period doubling and torus bifurcations from the magnitude of Floquet multipliers; switches `ISP` (branch points, period-doubling, torus) and `ILP` (folds) — [Imperial/Bristol lecture notes](https://www.ma.ic.ac.uk/~jswlamb/LDSG/grad0506/files/intro.pdf), [AUTO2000 quick reference](https://nlds.sdsu.edu:443/resources/auto2000_quick_ref.pdf)
- Not implemented in AUTO, according to the MatCont authors' paper on homoclinic continuation: "periodic normal forms for codimension 1 bifurcations of limit cycles, normal forms for codimension 2 bifurcations of equilibria, detection of codimension 2 bifurcations of limit cycles" (an older source; not re-checked against the present manual) — [De Witte et al., ACM TOMS preprint](https://webspace.science.uu.nl/~kouzn101/NBA/ACMTOMS-Hom.pdf)
- HomCont (in AUTO and in XPP) continues codimension-1 homoclinic and heteroclinic orbits and detects many codimension-2 singularities along them — [De Witte et al.](https://webspace.science.uu.nl/~kouzn101/NBA/ACMTOMS-Hom.pdf)
- PyCoBi 1.1.0 (2026-06-07, **[GPL v3]**, pure-Python wheel) wraps auto-07p for automated codimension-2 searches, and warns that recursive searches should be validated against a manual run on unfamiliar models — [PyPI pycobi](https://pypi.org/project/pycobi/), [PyCoBi docs](https://pycobi.readthedocs.io/en/latest/auto_examples/automated_continuation.html)

**MatCont (MATLAB; GUI and command line)**
- Newest download MatCont7p6.zip (5.6 MB), dated 2026-02-12 on SourceForge; MatContM (maps) folder last modified 2018-04-16; no licence shown on the files page — [SourceForge matcont files](https://sourceforge.net/projects/matcont/files/)
- Version 7p6 adds a delay-equation importer (delay differential and renewal equations reduced to ODEs by pseudospectral approximation of user-set order), Lyapunov exponents, event functions for Poincaré maps and enhanced homoclinic continuation; test cases include Mackey–Glass — [Liessi, Santi, Vermiglio, Thakur, Meijer, Scarabel, arXiv:2504.12785 (v3, 4 Nov 2025)](https://arxiv.org/abs/2504.12785)
- The 2019 manual has sections "Bifurcations and their normal form coefficients" (6.3) and normal form coefficients for limit cycle bifurcations (7.5.2) — [MatCont manual, Aug 2019](https://webspace.science.uu.nl/~kouzn101/NBA/ManualMatcontAug2019.pdf)
- The underlying mathematics: explicit formulas for the coefficients of the periodic normal forms for all codimension-1 bifurcations of limit cycles (Kuznetsov, Govaerts, Doedel, Dhooge, SIAM J. Numer. Anal. 2005), later codimension 2 (De Witte, Della Rossa, Govaerts, Kuznetsov, SIADS 2013) — [bibliographic record](https://bvbvf1.bib-bvb.de/vufind/PrimoRecord/cdi_proquest_journals_922255293)
- CL_MATCONTL computes normal form coefficients for fold and Hopf equilibrium bifurcations and for codimension-2 equilibrium bifurcations using multilinear forms up to order 3 — [CL_MATCONTL paper](https://www.academia.edu/54598280/CL_MATCONTL_a_continuation_toolbox_for_large_equilibrium_problems_in_MATLAB)
- For maps, critical normal form coefficients for all codimension-1 and -2 bifurcations are given by Govaerts, Khoshsiar Ghaziani, Kuznetsov and Meijer — [paper](https://webspace.science.uu.nl/~kouzn101/NBA/2paramNumerMaps.pdf)

**XPPAUT**
- "XPPAUT 8.0 Nov 2023" is the current version on Ermentrout's page, with Windows, macOS (universal binary) and Linux builds, a Python interface and a MATLAB plotting tool — [XPPAUT home](https://sites.pitt.edu/~phase/bard/bardware/xpp/xpp.html)
- Solves differential, difference, delay, functional, boundary value, integral and stochastic equations, up to 590 differential equations, with "over a dozen solvers"; offers equilibria and linear stability, one-dimensional invariant sets, nullclines and flow fields, Poincaré maps, a Marquardt–Levenberg curve fitter, animation, and AUTO built in — [What is XPP/XPPAUT](https://sites.pitt.edu/~phase/bard/bardware/xpp/whatis.html)
- The GitHub mirror is **[GPL-2.0]**, last pushed 2020-05-07 — [Ermentrout/xppaut](https://github.com/Ermentrout/xppaut)

**PyDSTool**
- 0.91.0 (2020-01-31) is the newest release; BSD; pure-Python wheel; last push to the repository 2023-06-14 — [PyPI PyDSTool](https://pypi.org/project/PyDSTool/), [releases](https://github.com/robclewley/pydstool/releases)
- Provides ODE, DAE and map generators with generated C code, hybrid and event-driven simulation, continuation "via PyCont with AUTO" (limit-cycle continuation reuses AUTO's C code), parameter estimation and symbolic tools — [PyDSTool project overview](https://pydstool.github.io/PyDSTool/ProjectOverview.html)
- Its own stated limits: "research code" in beta; no graphical interface; no PDEs; delays only as Dirac pulses in hybrid systems; no automatic differentiation; missing Poincaré maps, symbolic dynamics, BVP solvers and invariant manifold computations — [PyDSTool project overview](https://pydstool.github.io/PyDSTool/ProjectOverview.html)

**BifurcationKit.jl**
- v0.8.9, MIT ("Expat"), Copyright 2019 Romain Veltz; documentation built 10 November 2026 on Julia 1.10.13; last push 2026-11-11 — [Julia registry](https://github.com/JuliaRegistries/General/blob/master/B/BifurcationKit/Versions.toml), [LICENSE.md](https://github.com/bifurcationkit/BifurcationKit.jl/blob/HEAD/LICENSE.md), [docs](https://docs.sciml.ai/BifurcationKit/stable/)
- Equilibria: detects branch, fold and Hopf points, and the codimension-2 points Bogdanov–Takens, Bautin, cusp, zero-Hopf and Hopf–Hopf; computes normal forms of branch point, fold, Hopf, and of Bogdanov–Takens, Bautin, cusp, zero-Hopf and Hopf–Hopf; continues folds and Hopf points (minimally augmented), switches branches automatically and builds bifurcation diagrams — [capabilities](https://docs.sciml.ai/BifurcationKit/dev/capabilities)
- Periodic orbits by standard shooting, Poincaré shooting, orthogonal collocation and trapezoid; detects branch, fold, Neimark–Sacker and period-doubling points and the codimension-2 points R1, R2, R3, R4, GPD, NS–NS, Chenciner, fold–flip, fold–NS and PD–NS; normal forms for PD and NS (Poincaré return map or Iooss normal form); continuation of fold, PD and NS for shooting and collocation — [capabilities](https://docs.sciml.ai/BifurcationKit/dev/capabilities)
- Maps: fixed points, with normal forms for period doubling, Neimark–Sacker and branch points ("limited"); homoclinic orbits to hyperbolic saddles are in the plug-in HclinicBifurcationKit.jl (v0.1.1); delay equations in DDEBifurcationKit.jl (v0.0.5) — [capabilities](https://docs.sciml.ai/BifurcationKit/dev/capabilities), [registry HclinicBifurcationKit](https://github.com/JuliaRegistries/General/blob/master/H/HclinicBifurcationKit/Versions.toml), [registry DDEBifurcationKit](https://github.com/JuliaRegistries/General/blob/master/D/DDEBifurcationKit/Versions.toml)
- Aimed at "large-scale equations F(u, λ)=0", with matrix-free, dense and sparse eigensolvers, Newton–Krylov and "CPU and GPU support"; it calls itself "one of the few software packages" offering shooting beside finite differences and collocation for periodic orbits — [docs index](https://docs.sciml.ai/BifurcationKit/stable/)
- Its docs list the field: AUTO-07p, XPPAUT, MATCONT, PyDSTool and COCO ("very reliable and some address high codimensional bifurcations"); for large problems pde2path, Trilinos-LOCA, CL_MATCONTL, COCO, GetFEM, ff-bifbox, pyNCT, pacopy; deflated continuation in defcont; in Julia HomotopyContinuation.jl, Bifurcations.jl (unmaintained) and NumericalContinuation.jl — [docs index](https://docs.sciml.ai/BifurcationKit/stable/)

**COCO, DDE-BIFTOOL, pde2path (all MATLAB)**
- COCO: newest release coco_2025January28.zip (7.4 MB, 2025-01-28), "Toolboxes for parameter continuation and bifurcation analysis"; no licence shown on the files page — [SourceForge cocotools files](https://sourceforge.net/projects/cocotools/files/)
- COCO's design is object-oriented, a system of equations "decomposed into multiple object instances", and has been applied to delay differential equations — [Ahsan, Dankowicz, Li, Sieber, arXiv:2104.12261](https://arxiv.org/pdf/2104.12261)
- DDE-BIFTOOL: newest numbered release v3.1.1 (2017-04-05), an `alpha` folder modified 2024-01-28, status Beta — [SourceForge ddebiftool files](https://sourceforge.net/projects/ddebiftool/files/)
- DDE-BIFTOOL handles constant and state-dependent delays: steady states with fold and Hopf bifurcations, periodic orbits with folds, period doublings and torus bifurcations, connecting orbits; stability from rightmost characteristic roots and Floquet multipliers — [manual, arXiv:1406.7144 (v4, for version 3.1.1)](https://arxiv.org/abs/1406.7144)
- The DDE-BIFTOOL manual states that "the package does not detect bifurcations automatically because the computation of eigenvalues or Floquet multipliers may require more computational effort" — [manual PDF](https://arxiv.org/pdf/1406.7144)
- pde2path 3.2 (March 2025): continuation and bifurcation for systems of PDEs over bounded domains in 1, 2 or 3 dimensions; fold, branch and Hopf points and time-periodic orbits; needs MATLAB and the free OOPDE; "free software under the GNU GPL" **[GPL]** — [pde2path home](https://pde2path.uol.de/)

**Published values usable as cross-checks**
- BifurcationKit's extended Lorenz-84 tutorial (α = 1/4, β = 1, G = 0.25, δ = 1.04, γ = 0.987) prints, along the equilibrium branch in F, Hopf points at F = 2.85996783, 2.46723305, 1.61975642 and a branch point at F = 1.54664839 — [Lorenz-84 tutorial](https://docs.sciml.ai/BifurcationKit/stable/tutorials/ode/lorenz84/)
- Same tutorial, codimension 2: Bogdanov–Takens at (F, T) ≈ (1.4467165285461687, 0.02094013962410271) with a = 0.21442327431975305, b = 0.6065142321262069; Bautin at (F, T) ≈ (2.376359035000007, 0.05019751315044285) with ω = 0.6903670762730485, l₂ = 0.15577527690181162; zero-Hopf points at T = ±0.00012644/−0.00012655; Hopf–Hopf at T = 0.02627340; no cusp is reported — [Lorenz-84 tutorial](https://docs.sciml.ai/BifurcationKit/stable/tutorials/ode/lorenz84/)
- The tutorial says the model "is also treated in MatCont" and cites Kuznetsov et al. (2008), but does not state that the numbers agree — [Lorenz-84 tutorial](https://docs.sciml.ai/BifurcationKit/stable/tutorials/ode/lorenz84/)
- MatCont 7p6's paper uses the Mackey–Glass equation and a renewal equation as test cases — [arXiv:2504.12785](https://arxiv.org/abs/2504.12785)

**A different kind of continuation**
- Attractors.jl's "global continuation" tracks all attractors across a parameter, needs no initial guess of an orbit or its period, finds chaotic and quasiperiodic attractors, and gives nonlocal stability; it does not label local bifurcations or follow unstable branches and is not optimised for PDEs. Its authors report about 25 s for 1000 initial conditions against about 0.5 s for one branch by local continuation, and say local continuation "requires expertise and constant interventions" — [Attractors.jl comparison page](https://juliadynamics.github.io/Attractors.jl/dev/bfkit_comparison)

### Inferences
- Normal-form coefficients are the dividing line: AUTO-07p reports types and locations; MatCont and BifurcationKit also report coefficients. A new C++ core that reports coefficients can be held to MatCont (the reference derivations) and BifurcationKit (MIT, scriptable, Julia is installed on the development machine), and to AUTO only for locations.
- Three of the eight tools require MATLAB (MatCont, COCO, DDE-BIFTOOL, pde2path makes four); none of these can generate fixtures on a machine without a MATLAB licence. BifurcationKit.jl, AUTO-07p (Fortran with a Python CLUI, under WSL) and PyCoBi can.
- PyDSTool's newest release is from January 2020; whether it runs on Python 3.12 with current NumPy was not tested, and it should not be relied on for fixtures without a trial.
- The newest numbered releases of AUTO-07p (2021) and DDE-BIFTOOL (2017) are old; both are maintained slowly rather than abandoned (pushes in 2025 and an alpha folder in 2024).

### Gaps
- The licences of MatCont, COCO and DDE-BIFTOOL were not shown on the pages read; they must be read from the archives before anything is borrowed.
- The exact list of what AUTO-07p's present manual detects, and whether it reports any normal-form coefficient, was not confirmed from the manual itself (the repository page gave no text of it).
- Closed-form checks such as the Lorenz system's Hopf point at r = σ(σ+b+3)/(σ−b−1) ≈ 24.74 for σ = 10, b = 8/3 are standard but no source was fetched for them in this pass.
- No independent side-by-side feature table of these tools was found; the comparisons above are from the tools' own documents.
- KNUT (delay equations) and Trilinos-LOCA were named by sources but not examined.

## 2. General Analysis of Dynamical Systems: DynamicalSystems.jl, TISEAN, nolds, pyunicorn, pynamical, deeptime, JiTC*DE, SciML, SUNDIALS, PETSc TS, Dedalus, Chebfun

### Takeaway
DynamicalSystems.jl (MIT, v3.7.0) is by far the broadest single library for chaos and nonlinear time-series analysis (Lyapunov spectra, basins, global continuation, recurrence quantification, embeddings, dimensions, a very large family of complexity measures), but it has no local continuation and no invariant manifolds; the others are either integrators (SciML, SUNDIALS, PETSc, JiTC*DE, Dedalus, Chebfun) or narrow time-series toolkits (TISEAN, nolds, pyunicorn, pynamical, deeptime).

### Inferences
- No tool in this group computes invariant manifolds of fixed points and periodic orbits as a first-class result: DynamicalSystems.jl does not mention them, PyDSTool lists them as missing, XPPAUT computes "one-dimensional invariant sets" only.
- For fixtures on Windows with Python 3.12: nolds, pynamical, deeptime, JiTC*DE (which additionally need a C compiler when they compile, an assumption from their names not verified here), PySINDy and SciPy install from wheels; pyunicorn, Dedalus, petsc4py and PyRQA need a build and are better run under WSL. DynamicalSystems.jl needs only Julia.
- TISEAN is frozen at 2007 and GPL; it is the historical reference for `lyap_k`-type estimators but should be compared against, not copied.

### Gaps
- TISEAN's list of programs was not retrievable from the framed index page; the names of its routines are not recorded here.
- What nolds, pyunicorn and deeptime compute in detail was read only from their one-line summaries; their documentation was not opened.
- Whether JiTCODE's Lyapunov-exponent classes and PETSc TS's adjoint and event features meet the application's needs was not examined.
- No benchmark study comparing these libraries' speed on a CPU was found in this pass (DynamicalSystems.jl's page says only "really fast").

## 3. Rigorous and Topological Dynamics: CAPD, CHomP and Conley-index software, DSGRN, GAIO, interval arithmetic, persistent homology, LCS tools, braids

### Takeaway
Certification is available but almost entirely under GPL or in separate small packages: CAPD (GPL-3.0, C++) certifies trajectories, Poincaré maps and their derivatives; CHomP/pychomp2, CMGDB and DSGRN (all MIT) compute homology, Conley–Morse graphs and combinatorial dynamics of switching networks; GAIO.jl (MIT) does set-oriented numerics including Morse graphs and Conley indices. No source read gives wall-clock costs for standard proofs, and braid entropy from trajectories was found only in braidlab (MATLAB, GPL-3.0).

### Cited Findings

**CAPD**

## 4. Open Quantum Systems: QuTiP 5, QuantumOptics.jl, QuantumToolbox.jl, dynamiqs, scqubits, tensor networks

### Takeaway

## 5. Random Variables and Samplers

### Takeaway
Every mature library separates three things: a source of bits (engine, bit generator, key), a distribution object (density, sampling, statistics), and a sampler or inference algorithm that needs only a log density known up to an additive constant. Counter-based generators (Philox, Threefry) are now standard for reproducible keyed streams, in NumPy, JAX and, from C++26, the standard library; Boost.Random's documented generators include none. No mainstream library was found that represents a distribution by its score as a first-class object.

### Cited Findings

### Inferences
- The recurring separations are: (1) bits (engine / BitGenerator / key) from variates (distribution / Generator); (2) a distribution that can only be sampled (`Sampleable`) from one that also has a density (`Distribution`); (3) the target of inference, a bare log-density function up to a constant (Stan's `target`, BlackJAX's `logdensity_fn`, emcee's `log_prob_fn`, LogDensityProblems), from the sampler, a pair `init`/`step` over an explicit state; (4) constraining transforms (bijectors) from both; (5) storage of draws and diagnostics from the sampler (emcee's backends, ArviZ).
- Three representations therefore recur for "what is known of a distribution": a full object (sample, log density, cdf, quantile, moments); an unnormalised log density (enough for MCMC, and for SciPy's numerical inversion in one dimension); samples alone. A score-only representation is not a first-class object in any mainstream library found: gradient samplers obtain the score by differentiating the log density.
- Keyed counter-based streams (Random123, NumPy's Philox, JAX's Threefry, C++26's `philox_engine`) match the infrastructure's existing convention of draws keyed by what they are for; `philox4x32`'s constants are fixed by the C++ standard, which gives an implementation an exact bit-level reference in NumPy (`Philox`, 64-bit variant) and in Random123's known-answer tests.
- Portable variates are a separate problem from portable bits: NumPy guarantees only the integer stream for a seed, and JAX drops sequential equivalence; a C++ core that needs identical normals on every platform must own its transformation from bits to variates.
- Tools that can generate sampler fixtures on Windows with Python 3.12 from wheels: SciPy, NumPy, emcee, BlackJAX, NumPyro, PyMC, ArviZ, nutpie; Stan through CmdStan needs a C++ toolchain and so WSL on the development machine (an assumption from how CmdStan builds models, not verified here).

- No statement was found on cppreference that the algorithms of the standard distributions are unspecified (so that results differ between standard libraries); this is widely known and should be verified against the standard before it is written into a design.
- Boost's licence (Boost Software License 1.0) was not fetched; `boostorg/random` shows no licence file at its root.

## 6. Interactive and Project-Based Environments

### Takeaway
Among the environments examined, only The Virtual Brain organises work as explicit projects with a history of operations and a tree of results; COPASI, Berkeley Madonna, XPPAUT and MatCont are organised around one model file, and Modelica tools around libraries of models. Documented complaints are about dated or idiosyncratic interfaces (XPPAUT, in its author's own words), silent acceptance of wrong input, and model files that cannot be merged under version control (Simulink).

- pynamical's own summary is "Model, simulate, and visualize discrete nonlinear dynamical systems" (a library used from notebooks; MIT) — [PyPI pynamical](https://pypi.org/project/pynamical/)
- PyDSTool states that it has no graphical interface and is "a scripting environment for advanced users" — [PyDSTool project overview](https://pydstool.github.io/PyDSTool/ProjectOverview.html)

### Inferences
- Two organising schemes exist. Model-centred: one file holds a model, its settings and sometimes its results (COPASI's file, a Madonna model, an XPP `.ode` file). Project-centred: a folder with data, a history of operations and a tree of derived results (TVB). The second matches the infrastructure's Market Studio and is the one that records provenance (which operation, on what, produced what, and whether it is stale).
- The complaints that can be documented point to three requirements: text-based, mergeable project files (against Simulink's `.slx`); input validated with reasons (against XPPAUT's silent acceptance, reported by a third-party extension's developer); and results that leave the tool easily (XPPLORE exists only to get XPPAUT's output into another environment).
- Browser-only tools for phase portraits and bifurcation diagrams are small and single-purpose; none found is a general project environment.

### Gaps
- No user reviews or forum threads criticising Berkeley Madonna, COPASI, OMEdit, System Modeler, Insight Maker or NEST Desktop were found; only the sources' own descriptions. Berkeley Madonna's prices were not on the page read.
- OMEdit's features and the present licence text of OpenModelica (OSMC-PL and its GPL/AGPL mode) were not read from a primary page.
- Simulink's and Simscape's current release, and how Simulink Projects organise files, were not retrieved; Simscape was not examined.
- How COPASI's file organises tasks, reports and plots, and its `.cps`, SED-ML and COMBINE-archive support, were not on the page read.
- NEST Desktop's project model, storage and backends were not on its index page.
- MatCont's GUI organisation (systems, diagrams, curves) was not documented from a primary source here.

## 7. Integrated Coverage: (a) Classical and Open Quantum, (b) Stochastic, (c) Model Discovery, (d) Braids and Topological Tools, (e) a Project-Based Graphical Interface

### Takeaway
No single tool was found that combines all five; a search for one returned only PySINDy and its GUI wrapper SEED 2.0, which cover discovery for classical data alone. The closest are ecosystems of separate libraries (SciML with DynamicalSystems.jl and QuantumToolbox.jl in Julia; MATLAB with MatCont, braidlab and Simulink), each lacking at least a project interface and, outside MATLAB, braids. This is a claim of absence based on searches that found nothing, not a proof.

### Cited Findings
- A web search for software integrating classical dynamical systems, open quantum systems, stochastic simulation and equation discovery in one platform with a graphical interface returned only PySINDy and SEED 2.0; neither addresses quantum systems — [PySINDy paper](https://arxiv.org/pdf/2111.08481), [SEED 2.0](https://github.com/M-Vause/SEED2.0)
- **Julia's SciML with JuliaDynamics** covers, as separately registered packages: ODE, SDE and DDE solvers (DifferentialEquations.jl 8.1.1), continuation (BifurcationKit.jl 0.8.9), model discovery (DataDrivenDiffEq.jl 1.16.2), symbolic modelling (ModelingToolkit.jl 11.46.1), nonlinear dynamics and time series (DynamicalSystems.jl 3.7.0), open quantum systems (QuantumToolbox.jl 0.51.1, QuantumOptics.jl 1.2.10), interval arithmetic (IntervalArithmetic.jl 1.0.14), persistent homology (Ripserer.jl 0.17.0) — [registry DifferentialEquations](https://github.com/JuliaRegistries/General/blob/master/D/DifferentialEquations/Versions.toml), [registry BifurcationKit](https://github.com/JuliaRegistries/General/blob/master/B/BifurcationKit/Versions.toml), [registry DataDrivenDiffEq](https://github.com/JuliaRegistries/General/blob/master/D/DataDrivenDiffEq/Versions.toml), [registry DynamicalSystems](https://github.com/JuliaRegistries/General/blob/master/D/DynamicalSystems/Versions.toml), [registry QuantumToolbox](https://github.com/JuliaRegistries/General/blob/master/Q/QuantumToolbox/Versions.toml)
- The only Julia braid package found, Braids.jl, does braid-group algebra (composition, Burau representation, Dehornoy reduction) and was announced in 2018; it does not mention entropy or trajectories — [Braids.jl](https://www.github.com/jwvictor/Braids.jl), [announcement](https://jwvictor.github.io/writing/2018/02/05/introducting-braids-jl.html)
- **DynamicalSystems.jl** has no local continuation yet and does not mention invariant manifolds or quantum systems — [contents](https://juliadynamics.github.io/DynamicalSystemsDocs.jl/dynamicalsystems/stable/contents/)
- **QuTiP** covers closed and open quantum dynamics and stochastic (measurement) dynamics, and nothing classical — [QuTiP 5 paper](https://arxiv.org/html/2412.04705v2)
- **XPPAUT** has a graphical interface, ODEs, delay, stochastic and boundary value problems and AUTO in one program, limited to 590 equations; nothing quantum, no discovery, no braids — [What is XPP/XPPAUT](https://sites.pitt.edu/~phase/bard/bardware/xpp/whatis.html)
- **COPASI** has a graphical interface with ODE, SDE and Gillespie simulation and parameter estimation — [copasi.org](https://copasi.org/)
- **MATLAB's ecosystem** holds MatCont (GUI, continuation, normal forms, Lyapunov exponents since 7p6), braidlab (braids from data, entropy; GPL-3.0), COCO, DDE-BIFTOOL, pde2path and Chebfun as separate packages under different licences — [MatCont 7p6 paper](https://arxiv.org/abs/2504.12785), [braidlab](https://github.com/jeanluct/braidlab), [COCO files](https://sourceforge.net/projects/cocotools/files/), [pde2path](https://pde2path.uol.de/)
- **braidlab** is the only tool found that computes topological entropy of braids built from data; alternatives in Python and Julia do algebra and visualisation — [braidlab guide](https://arxiv.org/abs/1410.0849), [braidpy](https://braidpy.readthedocs.io/en/latest/)
- **The Virtual Brain** is project-based with a history of operations, for brain network models only — [TVB user guide: Project](https://docs.thevirtualbrain.org/manuals/UserGuide/UserGuide-UI_Project.html)
- **teaspoon** joins a library of dynamical systems, embedding, persistent homology and forecasting in one Python package (GPL-3.0), without a GUI — [teaspoon docs](https://teaspoontda.github.io/teaspoon/)
- **PyDSTool** aimed at integrated modelling, simulation, continuation and fitting, and lists Poincaré maps, symbolic dynamics and invariant manifolds as missing and has no GUI; its last release is from 2020 — [PyDSTool project overview](https://pydstool.github.io/PyDSTool/ProjectOverview.html), [PyPI PyDSTool](https://pypi.org/project/PyDSTool/)

### Inferences
- Coverage of the five requirements by the closest candidates, as far as the sources read show (yes / no / part):
  - SciML + JuliaDynamics + QuantumToolbox.jl: (a) yes, as separate packages with different state types; (b) yes; (c) yes; (d) persistent homology and intervals yes, braids no; (e) no project GUI found.
  - MATLAB with MatCont, braidlab, Simulink: (a) classical yes, quantum only through third-party toolboxes not examined; (b) part; (c) not examined; (d) braids yes (GPL), rigorous no; (e) MatCont's GUI and Simulink projects, not one environment; commercial base.
  - XPPAUT: (a) classical only; (b) yes; (c) curve fitting only; (d) no; (e) a GUI around one model file.
  - QuTiP: (a) quantum only; (b) quantum trajectories; (c) no; (d) no; (e) no.
  - COPASI: (a) classical reaction networks only; (b) yes; (c) parameter estimation, not structure discovery; (d) no; (e) a GUI around one model file.
  - The Virtual Brain: (a) classical neural mass models only; (b) stochastic integration (not verified here); (c) no; (d) no; (e) yes.
- The gap a new application would fill is therefore the conjunction, not any one part: one model description with classical, stochastic and open quantum evolutions under one project and provenance model; discovery from data in the same project; and topological readings (braids of trajectories, entropy bounds) beside the numerical ones. Each part has a reference implementation to be held to (BifurcationKit and MatCont; DynamicalSystems.jl; QuTiP; SciML's SDE orders; PySINDy; braidlab; CAPD for enclosures).
- Because braidlab and CAPD are GPL and MATLAB or C++ respectively, the braid and rigorous parts must be written afresh under MIT and only compared against them.

### Gaps
- The claim that no integrated tool exists rests on one web search for such a platform, one for braid software, and the feature lists of the tools above; commercial suites (Wolfram Language's own dynamical, quantum and data-driven functions; MATLAB toolboxes; JuliaHub's commercial modelling products) were not examined feature by feature and could cover more than is recorded here.
- Whether QuantumToolbox.jl and DynamicalSystems.jl can share one model description (for example through ModelingToolkit) was not checked.
- Model discovery for stochastic and for open quantum systems (learning a Lindbladian or an SDE from data) was not researched; no tool for either is recorded here, and none is claimed absent.
- Interactive applications of the Julia ecosystem (the registered InteractiveDynamics.jl 0.24.0 and what DynamicalSystems.jl now offers interactively) were not examined.
